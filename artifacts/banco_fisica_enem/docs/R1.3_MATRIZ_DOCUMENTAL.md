# R1.3 — Matriz documental e preparação da ingestão

## 1. Objetivo
Transformar o catálogo R1.2 em matriz operacional: unidade documental, caderno-âncora, identidade canônica vs variante, rastreio até o PDF oficial — **sem extração e sem download**.

## 2. Estrutura documental
```
EXAM (ENEM)
 └── APPLICATION (regular | ppl | reaplicacao | acessibilidade | digital)
      └── DAY (1 | 2)
           └── BOOKLET (número + cor)
                ├── PROOF PDF
                ├── ANSWER KEY PDF
                └── QUESTION VARIANT  →  CANONICAL QUESTION
```

Camadas coexistentes:
- `LEGACY_2009_2023` — JSON atuais; IDs `ENEM-FIS-…` intocados.
- `OFFICIAL_2024_2025` — documentos INEP + futuras variantes.

## 10–12. Canônica, variante, identidade

**Canônica** (`ENEM-CN-{ANO}-D{DIA}-CAN-{SEQ}`): um nó pedagógico. SEQ só existe depois do matching entre cadernos. Não usa o número impresso de um caderno como identidade.

**Variante** (`ENEM-CN-{ANO}-{APP}-D{DIA}-C{CADERNO}-Q{N}`): ocorrência física. `official_question_number` mora aqui. N do Caderno 7 **não** é assumido igual ao N do Caderno 5.

APP: `REG` agora; futuro `PPL`, `REAP`, `ACES`, `BEL`.

Ponte legacy: `canonical_questions.legacy_question_id` → `questions.id` (não preenchida nesta fase).

## 13. Gabarito
PROOF → BOOKLET → VARIANT ← ANSWER KEY  
`answer_source = INEP`  
`answer_status`: official | pending_verification | corrected_by_official_revision | annulled  
“official” = veio do PDF de gabarito, não verificação matemática.

## 14. Questões anuladas
Modelo: `question_status = annulled` na canônica e/ou `answer_status = annulled` na variante.  
Anulação CN 2024 citada pelo MEC **não gera registro** agora.

## 15. Imagens
`question_images`: 0..N por variante; page/crop/sha256/extraction_status. Nada extraído.

## 16. Hash
`hash_status = pending_download`. `document_sha256` e hashes de imagem/conteúdo = null. Nenhum valor inventado.

## 17. Compatibilidade legacy
Não converter 2009–2023. Não reprocessar. Não alterar IDs. UI e classificador permanecem na camada legacy até publicação futura.

## 18. Pipeline futuro (não executado)
INEP PDF → SHA-256 → metadados → segmentação de página/questão → texto/imagem/alternativas → matching gabarito → variante → matching canônico → classificação → validação → publicação.

Stub: `scripts/PREPARATION_ONLY_ingest_pipeline.py` (não processa PDF).

## 19. Duplicação / matching entre cadernos
Proibido casar só por número, posição ou cor. Futuro: texto normalizado + alternativas + imagens + estrutura + hashes + similaridade.

## 20. Validações
32 documentos; JSON válido; 619/140 intactos; nenhum PDF baixado; nenhum hash preenchido; nenhuma questão 2024/2025 no banco de itens.

## 21. Riscos
Matching entre cores só depois da extração; anulação 2024 por cor; páginas INEP podem republicar arquivos; schema ainda não instanciado.
